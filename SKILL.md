# kp-generator

Генерирует коммерческое предложение агентства как HTML-колоду, которую рендерит в
`kp.pdf` (одна альбомная страница = один слайд) и набор `png/slide-NN.png` —
плюс `cover-message.txt`, короткий продающий текст, с которым КП отправляется
клиенту. Дизайн — единый фирменный шаблон (см. «Визуальный дизайн» ниже), контент —
то, что ты соберёшь из описания проекта.

## Когда применять

Пользователь просит собрать КП / коммерческое предложение / презентацию для клиента /
sales deck по проекту — обычно свободным текстом ("нужно КП для клиента X на
разработку Y, стоимость такая-то, сроки такие-то").

## Workflow

1. **Прочитай `references/content-schema.md`** — там точная схема `content.json`,
   какие поля обязательны, какие опциональны, как помечать неизвестные данные (`"TBD"`).
2. **Собери контекст по проекту**: клиент/компания, что входит в MVP/первую версию,
   что входит в FULL/расширенную версию — выведи это из ТЗ, описания, переписки,
   а не переспрашивай по умолчанию (правило «выводи из проекта» в
   `references/kp-writing-guide.md`). Спрашивай пользователя только если этой
   информации нет вообще нигде.
3. **Предложи цену и сроки, прежде чем их фиксировать**: изучи полное ТЗ и материалы
   проекта, прикинь минимальную конкурентную стоимость и сроки — исходя из того, что
   реализация идёт вайб-кодингом силами команды разработчиков (быстрее и дешевле
   классической разработки, цель — выигрышная цена по рынку). Покажи расчёт
   пользователю и дождись подтверждения/правки, прежде чем фиксировать цифры в
   `pricing`/`timeline`. Подробный алгоритм — раздел «Цена и сроки» в
   `references/kp-writing-guide.md`.
4. **Собери `content.json`** из подтверждённых данных, руководствуясь
   `references/kp-writing-guide.md` (тон, MVP/FULL структура, что делать при нехватке
   данных). Не выдумывай цифры — единственное жёсткое правило. `contacts` и
   `terms.paymentTerms` в JSON не указывай — это фиксированные значения агентства,
   подставляются автоматически (см. «Бренд и агентские политики» ниже).
5. **Проверь критичные поля** перед рендером: `scope.stages`, `pricing` (`items` или
   `packages`). Если их нечем заполнить даже после шага 3 — задай пользователю один
   компактный уточняющий вопрос, не запускай рендер с пустышками.
6. **Запусти генератор** — формат всегда `pdf,png`, ничего не уточняй:
   ```bash
   node scripts/generate.js --content <path/to/content.json> --format pdf,png --out ./output/<outputSlug>
   ```
   Скрипт сам провалидирует содержимое (`scripts/validate-content.js`) и выведет в
   stdout JSON с путями к результату (`{"pdf": "...", "png": ["..."]}`). Если
   валидация не прошла — скрипт вернёт ненулевой код и список ошибок в stderr;
   не пытайся обойти это, а исправь `content.json` или уточни у пользователя.
7. **Напиши сопроводительное сообщение** — короткий продающий текст для отправки
   клиенту вместе с файлом (не саммари презентации, а текст письма/сообщения поверх
   вложения). Пиши сам, по правилам `references/cover-message-guide.md`, и сохрани
   как `<outDir>/cover-message.txt` — этот шаг обязателен для каждого КП, не только
   когда об этом попросили отдельно.
8. **Покажи результат пользователю**: пути к файлам КП, текст сопроводительного
   сообщения целиком (чтобы можно было сразу скопировать), и кратко резюмируй, какие
   разделы вошли в КП — явно перечисли поля, помеченные `"TBD"`, если такие есть.

Скилл только генерирует файлы. Отправка получателю (клиенту) — не его задача,
это делает сам агент своими средствами, если пользователь попросит.

## Бренд и агентские политики

`assets/agency-defaults.json` задаёт то, что не зависит от конкретного проекта
и всегда одинаково в каждом КП (см. `scripts/render-html.js`, `renderHtml`, —
подставляется при рендере и переопределяет любые значения из `content.json`):

- **Контакт** — всегда Марат Дамирович, `@educ_founder` (`defaultContact`).
  Не спрашивай контакт у пользователя и не проси Claude придумывать другого
  контактного лица.
- **Условия оплаты** — всегда поэтапная оплата (`defaultPaymentTerms`):
  предоплата за этап → работа → приёмка → предоплата следующего этапа. Никогда
  не предлагай схему «50/50» или единую предоплату за весь проект.

Если агентская политика изменится — правь только `assets/agency-defaults.json`,
код и остальные скиллы трогать не нужно.

## Визуальный дизайн

Настроен под агентство **Melory** (дизайн ориентирован на melory.agency): тёмная
тема, зелёный акцент, лого-иконка + жирный текстовый логотип "Melory". Управляется
тремя файлами в `assets/`:

- `assets/logo.png` — иконка-марка Melory (взята с их сайта). Рядом с ней в шапке
  каждого слайда рендерится текстовый wordmark `brand.agencyName` (класс
  `.logo-lockup` в `templates/styles.css`) — само название нигде не зашито в код,
  берётся из `brand.json`.
- `assets/brand.json` — цвета (`colors.*`, тёмная палитра: `surface` #0E0E0E,
  `accent` #5FCF80 и т.д.) и шрифты (`fonts.heading`, `fonts.body`). Логотип можно
  заменить на svg/png/jpg/webp — mime определяется по расширению автоматически.
- `assets/fonts/` — Inter (400/600/700/800, кириллица + латиница) как woff2,
  встраиваются в HTML как data URI, рендер работает офлайн. **Важно**: сайт-референс
  использует шрифты Clash Display/Satoshi (Fontshare) — они НЕ поддерживают кириллицу
  (проверено через fontTools/cmap), поэтому для текста на русском используется Inter
  800 как визуально близкая по «плотности» замена для крупных заголовков.

Если поменяешь `fonts.heading`/`fonts.body` на другой шрифт — положи его woff2
(с кириллицей!) в `assets/fonts/` и поправь `scripts/render-html.js`
(`FONT_FILES`/`buildFontFaceCss`), чтобы рендер его подхватывал.

После правки бренда прогони тестовую генерацию и посмотри PNG глазами:
```bash
npm install   # один раз — тянет Puppeteer/Chromium
node scripts/generate.js --content examples/sample-content.json --format pdf,png --out ./output/test
```

## Структура content.json (кратко)

`meta`, `cover`, `problem`, `solution`, `scope`, `pricing` — обязательны.
`timeline`, `cases` — опциональны, слайд рендерится только если раздел есть в JSON.
`terms` и `contacts` — опциональны в JSON, но слайды рендерятся всегда:
`paymentTerms`/`personName`/`messenger` подставляются автоматически из
`assets/agency-defaults.json`, указывать их в JSON не нужно. Полная схема —
`references/content-schema.md`, пример — `examples/sample-content.json`.
